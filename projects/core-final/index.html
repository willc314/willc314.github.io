Dialect Analysis

I wrote a short program that tests whether a widely used piece of language software rates the same sentence differently depending on which dialect of English it is written in.

William  ·  Computer Science

Summary

Question

Does a widely used piece of language software judge the same statement differently depending on which dialect of English it is written in?

Data

2,019 published sentence pairs from Groenwold et al. (2020). Each pair says the same thing twice, once in African American English and once in standard English.

Method

Send both versions of every pair through the same publicly available sentiment classifier, then report the results separately for each dialect instead of as one combined figure.

Finding

What I tested

A program that decides whether writing sounds positive or negative

Sentiment classifiers are ordinary and everywhere. They sit behind systems that flag social media posts for review, sort customer complaints, screen job applications, and score student essays. You give one a sentence and it returns a judgement, positive or negative, along with how confident it is.

I tested whether that judgement changes when the same thing is said in African American English rather than in the standard written English the software was mostly trained on.

This matters because African American English is not broken English. It is a dialect with consistent rules that linguists have documented for decades. If a program rates it lower, it has not found mistakes. It has quietly decided that one way of speaking is the correct one.

The sentences

Why I did not write the test data myself

I am not a speaker of this dialect. Anything I invented would have been an imitation, and if the software rated my imitation badly I would have learned nothing except that my imitation reads as fake.

So I used a published set of 2,019 sentence pairs from a 2020 research paper by Groenwold and colleagues. Each pair says the same thing twice. One version is a real post written by a real person. The other was written by human annotators in standard English.

This brings up a limitation. I would not be able to do this project alone, I had to use work done by another group of people before my tests were even possible.

African American English

Boy you can say anything you wanna I don’t give a shit, noone else can have ya

Standard English

You can say anything you want to, I don’t care, noone else can have you

This pair also shows a problem with my own data. The standard version turns “I don’t give a shit” into “I don’t care,” which is milder. Rewriting something in plain words tends to soften how strongly it is expressed, so some of the difference I measure may come from the translating rather than from the dialect.

Credit where it is due

What I borrowed and what I built

Not mine

The classifier is an off-the-shelf model that anyone can download in one line. I did not train it or write it. That is deliberate. I wanted to test a well documented thing a working developer would actually use, not something that I come up with on the spot.

Mine

Pairing the sentences, checking they line up, running both sides, reporting the outcome separately for each dialect instead of as one figure, and testing whether the difference could be chance.

This division is part of the argument. While the recognition is always available, the comparison and tests were not.

The part that does the actual comparison 
for aae_sentence, standard_sentence in pairs:
    a = classifier(aae_sentence)
    b = classifier(standard_sentence)
    difference.append(a.positive_score - b.positive_score)

Same meaning, opposite verdicts

Where my own average misleads

The number I would have reported hides what it is made of

Average change across all pairs

Change for the middle pair

If I had published only the average, I would have implied that the software treats this dialect worse across the board. It does not. Most sentences are barely affected and a minority are hit hard. That is a different problem than what I expected, but it might be even worse, as it can stay hidden until you get hit by it.

The obvious objection

Is it just swearing?

The most reasonable challenge to all of this is that the posts contain words any program would rate as negative, so I might be measuring vocabulary rather than dialect. So I ran it again with every pair containing two frequently occurring words removed, one of them a racial slur.

Limits

What these numbers do not say

My whole argument is that people publish figures without saying what those figures hide. It would be strange to do that with my own.

  • The posts date from around 2013. That might not be how anybody writes now.
  • The standard English versions were written by annotators. Rewriting something in plain prose tends to flatten how strongly it is expressed, so part of the gap may come from the act of translating rather than from the dialect itself.
  • This test is only with one program, a different program might have different results.
  • The two words I removed are not the only loaded vocabulary in the data. A longer list would test this harder.
  • A very small p-value means a pattern this consistent is unlikely to be chance. It says nothing about whether the size of it matters.

What I take from it

My field solved a problem shaped like this once already

Accessibility, meaning whether software works for people with disabilities, did not improve because developers became kinder. It improved because it stopped being a matter of conscience and became a matter of process. There is an agreed standard, a tool that checks automatically, a required step before code ships, and legal consequences for ignoring it.

None of that exists for the question I asked here. There is no standard defining what counts as passing, no tool that runs by default, and no cost at all to never checking. The check itself took about sixty lines.

What I can do about this might not that I will be a better person about this, but that I will be aware of and report results by groups when I build anything that scores people. Such as, asking who is missing from the test data, and getting someone else with different ideas to check it before shipping anything out.
